# issue #48 音声ログ出力時間の検証

## 目的・対象範囲
- USB シリアル未読時の音声途切れを調べるため、`RealtimeLLMBase::streamAudioDelta()` の既存ログ出力時間を測定する。
- `Serial.setTxTimeoutMs(0)` による対策はまだ適用しない。

## 主な変更ファイル
- `src/llm/RealtimeLLMBase.cpp`
- 本ステアリングファイル

## 実装方針
- 同 cpp 内に `REALTIME_AUDIO_LOG_TIMING` マクロを置き、`1` で有効、`0` で無効にする。外部からのビルド定義を優先し、検証時の既定値は `1` とする。
- `esp_timer_get_time()` により単調増加の実時間をマイクロ秒単位で取得する。
- 既存の `audio base64 size` と `audio pcm16 size` の各 `Serial.printf()` の直前・直後だけを計測する。デコード時間、再生待ち、画面更新時間は計測に含めない。
- 2箇所のログ出力について、1回あたりの所要時間の最大値を関数内の static 変数1個に保持する。起動後の初回呼び出しから累積し、再起動でリセットする。
- 初回と最大値更新時に `avatar.updateSubWindowTxt()` で `Log max: xxx.xxx ms` を左上付近（x=0, y=0, 幅約200, 高さ50）へ表示し、サブウィンドウを有効にする。毎チャンクの画面更新を避け、検証への負荷を抑える。
- マクロ無効時は計測、最大値保持、表示、追加ヘッダーをコンパイル対象から外す。

## 設計上の注意点・副作用・戻し方
- Gemini Live に限らず、この共通関数を通る音声出力が対象となる。
- 画面表示は既存のサブウィンドウと共有するため、検証中は他のサブウィンドウ表示と競合し得る。
- 画面更新自体の負荷は残る。測定値はログ呼び出しの実経過時間であり、タスク切り替え等も含むため USB 待ち時間だけを厳密に分離するものではない。
- 恒久的な新機構ではなく一時的な検証コードとし、今回 `doc/fw_design.md` は変更しない。
- マクロを `0` にすれば検証処理を無効化できる。完全撤去は今回の cpp 差分のみを戻す。

## 確認方法
- マクロ有効・無効で `m5stack-cores3-realtime` をビルドする。依存取得にネットワークが必要なら実行前に確認する。
- 実機で USB 接続のままシリアルモニタを開閉し、少し長い Gemini Live 応答で最大値と音声途切れの関係を確認する。
- 最大値が減らないこと、再起動でリセットされること、左上表示が読めることを確認する。
- ビルド確認と実機確認は区別して報告する。

## レビュー
- ユーザー了承済み。上記方針で実装。

## 確認結果
- CoreS3 Realtime の既存 `idedata.json` のコンパイル設定と Xtensa コンパイラを用い、変更 cpp の `-fsyntax-only` をマクロ `1` / `0` の両方で確認済み。
- PlatformIO はユーザー領域キャッシュの書き込み権限エラーがあるため、全体ビルド・リンク確認は未実施。依存ライブラリのネットワーク取得は行っていない。
- 実機での表示位置、最大値、音声途切れとの比較は未確認。

## 検証終了・撤去方針
- ユーザーが現象再現と対策後の改善を確認し、検証コードの削除を明示指示した。
- `src/llm/RealtimeLLMBase.cpp` の `REALTIME_AUDIO_LOG_TIMING` 関連コードと追加ヘッダーを削除し、検証前に戻す。USB シリアル対策と設計メモは保持する。
- 対象 cpp が HEAD と一致すること、および `git diff --check` で確認する。撤去の主な変更ファイルは対象 cpp と両ステアリングファイル。検証表示はなくなり、再計測時には検証差分の再適用が必要となる。
