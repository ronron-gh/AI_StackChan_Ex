# SanoTTS の区間蓄積再生とビルド時切り替え

状態: 実装と両方式のビルド確認済み。CoreS3 実機確認待ち。

## 目的と影響範囲

- PSRAM 上の推論 arena では `saan_stream_pull()` が再生速度に追いつかず、既存の逐次再生で音が途切れる。句読点・改行・入力上限で分割した各区間の PCM を合成し終えてから再生する方式を追加する。
- 既存の逐次再生方式も残し、CoreS3 の SanoTTS ビルドフラグで選択する。`TTSBase::stream()` の同期契約、分割規則、マイクとスピーカーの復元は維持する。
- 対象は `src/tts/SanoTTS.cpp`、`platformio.ini`、SanoTTS の利用文書と設計メモ。作業中の `src/main.cpp` のヒープ計測差分と arena 配置ログは保持する。

## 実装方針

- ビルドフラグ `SANOTTS_BUFFERED_PLAYBACK` が有効なら区間蓄積再生、無効なら従来の逐次再生とする。SanoTTS の既定環境では有効にし、フラグを外すと従来方式に戻せるようにする。
- 日本語解析、`saan_stream_init()`、PCM 変換は共通にする。蓄積方式では予測フレーム数から必要な PCM 容量を計算し、既存の30秒上限と乗算オーバーフローを検査してから PSRAM に確保する。全サンプルを埋めて正常終了した場合だけ `playRaw()` に渡す。
- 再生中は PCM バッファを保持し、ソース消費と DMA 排出を待ってから解放する。タイムアウト、確保失敗、推論失敗、再生失敗でもスピーカーとマイクを復元する。`getLevel()` は今回の主目的から外れるため、現行動作を維持する。
- 区間間には蓄積待ちの無音時間が生じる。区間境界の完全な連続再生は保証せず、まず区間内の途切れ解消を実機で確認する。PSRAM 使用量は最大30秒の16-bit mono PCMで約1.26 MiBとなり、確保失敗はログで分かるようにする。
