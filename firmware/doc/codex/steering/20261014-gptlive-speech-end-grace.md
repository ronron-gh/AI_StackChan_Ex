# GPTLive の句読点での途中マイク復帰を抑制

## 目的
発話内の400 msを超える間でマイクへ戻る問題を修正する。発話終了と受信途絶の猶予を1200 msにそろえ、再生リングが空になっただけでは発話を終了しない。

## 対象範囲・主な変更ファイル
- src/llm/ChatGPT/GPTLive.h / GPTLive.cpp: 終了判定の定数、発話状態とマイク復帰条件、ログ。
- doc/fw_design.md: 既存の GPTLive Audio Playback 節を更新。
- 本ステアリング: 確認結果を記録。
前回の未コミット差分を維持する。基底クラス、他のLLM、TTS、RMS閾値300／150、発話前100 msの保持、PSRAM容量は変更しない。

## 実装方針
1. PCM上の無音終了猶予を400 ms（9600 sample）から1200 ms（28800 sample、24 kHz）へ変更する。20 ms判定窓60個の無音で待機へ戻り、以後の無音を破棄する。継続閾値以上の音声が戻れば無音累計をゼロにする。
2. 有効PCMの受信自体が1200 ms途絶えた場合も発話終了とする。この壁時計による終了は、PCMサンプル数で数える無音終了と分離する。無音PCMが届き続ける場合はサンプル数の終了判定で復帰する。
3. リングとスピーカーが空でも、発話継続中かつ受信途絶1200 ms未満ならスピーカー側と音声mutexを維持する。現在の「リングが空になって150 msで復帰」は、この状態で発火させない。
4. 無音または受信途絶で終了を確認し、蓄積PCMとSpeakerの再生が完了した後に既存の150 msの終了猶予でマイクを復帰する。新しい発話が来た場合は復帰待ちを解除する。
5. 途中の20 ms未満の判定窓を処理する既存の150 ms条件は、末尾を失わないための窓確定として維持する。この条件自体では発話を終了しない。
6. 判定ログを1200 msの条件に合わせ、PCM無音と受信途絶の終了理由を識別できるようにする。切断・異常・モード停止の強制的な後始末と手動録音停止の尊重は維持する。

## 注意点・副作用
- 発話終了後の録音復帰は遅くなる。1200 msより長い発話内の間では途中復帰し得る。
- 終了までに保持する無音PCMが増えるが、512 KiBのリング容量と再生領域の寿命・満杯時の復旧方針は維持する。
- 発話継続中のリング枯渇時も音声mutexを保持するため、他の音声処理は終了または受信途絶判定まで待つ。

## 確認方法
- 発話→500〜1000 msの無音→発話で、継続状態とスピーカー側が維持されることを確認する。
- 1200 ms以上の無音が連続受信される場合、発話終了後にリングとSpeakerを排出してマイク復帰することを確認する。
- リングが空で受信途絶が150 ms／1199 msでは復帰せず、1200 ms以上で終了できることを確認する。
- 末尾の短い窓、受信再開、手動録音停止、切断・モード停止を確認する。
- m5stack-cores3-realtime / m5stack-core2-realtimeをビルドし、変更内容に応じて他のRealtime／TTS構成も確認する。依存追加取得が必要なら事前確認する。
- 句読点での継続と応答終了後の録音再開はユーザー環境の実機で確認する。

## 戻し方
今回の終了猶予と復帰条件の差分だけを戻す。既存のリング再生・無音判定と他の未コミット差分は維持する。

## 実装・確認結果

- AUDIO_SPEECH_END_MS / AUDIO_RECEIVE_TIMEOUT_MS をそれぞれ1200 msとし、無音サンプル数は前者から28800 sampleに算出する。末尾の窓確定と終了後の150 ms猶予は維持する。
- processAudioPlaybackで発話継続中のリング枯渇を待機扱いとし、終了後の150 msタイマーを開始しない。PCM無音と受信途絶で終了した後のみ、リング・Speakerの排出後にマイク復帰へ進む。
- 静的確認: 500 ms／1000 msの無音は25／50窓で60窓未満のため終了しない。継続閾値以上の窓では無音累計をリセットする。
- 静的確認: 受信途絶150 ms／1199 msでは発話終了せず、1200 ms以上で終了する。受信継続中の無音はPCM側の60窓で終了する。受信再開で発話が検出された場合は再生追加により終了待ちを解除する。
- 再生中のPCM領域は完了まで保持し、1200 ms判定だけで未再生音声を破棄しない。切断・異常・モード停止の強制リセット、手動停止後に録音を再開しない既存の制御は変更していない。
