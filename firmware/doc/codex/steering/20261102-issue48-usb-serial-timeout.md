# issue #48 USB シリアル送信待ちの対策

## 目的
- 検証コードによる実機確認で再現した、シリアルモニタを閉じた状態でのリアルタイム音声途切れを対策する。

## 対象範囲・主な変更ファイル
- `src/main.cpp`: 起動時の HWCDC 送信タイムアウト設定。
- `doc/fw_design.md`: ログ送信待ちを無効化する意図とログ欠落の可能性を既存の関連節に短く記載。
- 本ステアリングファイル。

## 実装方針
- `setup()` の `M5.begin(cfg);` 直後に、次の処理を追加する。
  ```cpp
  #if ARDUINO_USB_CDC_ON_BOOT && ARDUINO_USB_MODE
    // USB シリアル未読時の送信待ちで音声処理を止めない。
    Serial.setTxTimeoutMs(0);
  #endif
  ```
- サービスや機種名ではなく Serial が HWCDC となる条件で適用する。該当する CoreS3 / AtomS3R の全モードが対象となり、UART Serial や USB CDC の別実装には適用しない。
- 既存のログと音声処理は変更しない。`REALTIME_AUDIO_LOG_TIMING` の検証コードと現在の有効状態を保持し、対策後の最大時間を比較可能にする。

## 根拠・設計上の注意点
- ローカル arduino-esp32 の `HWCDC.cpp` で、初回のホスト受信後に既定タイムアウトを100msへ変更する処理を確認した。
- `setTxTimeoutMs(0)` は明示設定フラグも立てるため、以後の接続で既定の100msへ変更されるのを防ぐ。
- 送信バッファや送信ロックが空かない場合、待たずに終了するためログの一部が欠ける。全ログ保存より音声処理の継続を優先する。
- これは USB 送信待ちを抑える対策であり、ログ整形や描画等を含めた全処理時間がゼロになるわけではない。
- 戻す場合は追加する条件付き設定ブロックと対応する設計メモのみを取り除く。既存の検証コードや他の作業差分は戻さない。

## 確認方法
- 可能な範囲で CoreS3 / Core2 / AtomS3R の Realtime 環境をビルドし、条件分岐を確認する。
- PlatformIO の権限制約等で全体ビルドできない場合、既存コンパイル設定を用いた構文確認を行い、全体ビルドとは区別して記録する。
- 依存取得にネットワークが必要なら実行前にユーザーへ確認する。
- 実機では再起動後、USB 接続のままシリアルモニタを開いて受信後に閉じ、長い Gemini Live 応答で音声途切れと最大ログ時間を比較する。最大値は再起動でリセットされる。
- 未接続起動、モニタ未起動、モニタ再接続も可能な範囲で確認する。

## レビュー
- ユーザー了承済み。上記方針で実装。

## 確認結果
- CoreS3 Realtime の既存 `idedata.json` と Xtensa コンパイラで `src/main.cpp` の構文確認が成功。
- 同じ CoreS3 設定で USB_MODE / CDC_ON_BOOT をそれぞれ `1/0`、`0/1` にした場合も構文確認が成功し、HWCDC 以外の条件では追加呼び出しが除外されることを確認。
- `git diff --check` 成功。
- PlatformIO の既知のキャッシュ書き込み権限制約があるため全体ビルド・リンクは未実施。Core2 / AtomS3R の環境別ビルドと対策後の実機確認も未実施。ネットワークでの依存取得は行っていない。
- 既存の音声ログ時間検証コードは変更せず保持。
- その後、ユーザーが実機で改善を確認。明示指示により音声ログ時間検証コードを撤去し、USB シリアル対策は保持する。
