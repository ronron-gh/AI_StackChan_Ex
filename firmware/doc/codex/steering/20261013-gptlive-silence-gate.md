# GPTLive の無音出力によるマイク復帰阻害を解消

## 目的
無音の session.output_audio.delta が連続してもマイクを使用できるよう、PCM の音量に基づいてスピーカーへ切り替える。

## 対象範囲・変更ファイル
- src/llm/ChatGPT/GPTLive.cpp / GPTLive.h: デコード後の無音判定、発話開始前保持、発話終了判定、判定ログ。
- doc/fw_design.md: 既存の GPTLive Audio Playback 節を更新する。
- 本ステアリング: 実装結果・確認結果を記録する。
基底クラス、既存 TTS、他の LLM、接続・モデル設定は変更しない。前回の未コミット差分を維持する。

## 実装方針
1. PCM16 / モノラル / 24 kHz を 20 ms（480 sample）単位で判定する。delta の境界で判定窓が分断されても次回へ持ち越す。
2. RMS の開始閾値を 300、継続閾値を 150 とする初期案。PCM16 の振幅単位で、平方和は 64 bit としてオーバーフローを避ける。開始と継続に異なる閾値を使い、状態の頻繁な変化を抑える。
3. 発話待機中の無音は再生リングに追加せず、直前 100 ms（4800 byte）のみを PSRAM に循環保持する。発話検出時にこの先行保持分と検出窓を順にリングへ追加し、語頭の欠落を抑える。判定窓も PSRAM に確保する。
4. 発話中は短い無音を含めて PCM をリングへ追加する。継続閾値未満が 400 ms（9600 sample）続いたら発話待機へ戻り、それ以降の無音を捨てる。猶予は受信した PCM のサンプル数で数え、受信速度に左右されないようにする。
5. 再生リングと Speaker の両方が空になってから、既存の 150 ms の壁時計猶予でスピーカーを停止しマイクを復帰する。破棄した無音はこの猶予をリセットしない。入力が途絶えた場合の復帰も維持する。
6. 切断、異常、モード停止で判定状態・途中の窓・先行保持分をクリアする。通常の再生終了と異常リセットを分け、通常終了時に保持している新しい無音窓を不必要に消さない。
7. RMS の一定期間の最小／最大値と判定遷移を低頻度でログに出し、実機で閾値を調整できるようにする。PCM 内容そのものはログに出さない。

## 注意点・副作用
- 閾値と 400 ms は実機未調整の初期値。弱い発話の見逃し、ノイズによる誤判定、長い発話内の間での切替は実機で確認する。
- 再生中の領域を使用量に含める既存の寿命・排他制御を維持する。満杯時は有効 PCM を部分追加せず、既存の異常復旧へ移る。
- 手動録音停止を上書きしない。半二重方式は維持し、再生中のユーザー音声は送信しない。
- 保持・判定用 PSRAM は約 5.6 KiB 追加。確保失敗時は既存の音声無効化・復旧方針に従う。

## 確認方法
- 全ゼロが連続する場合、発話→400 ms以上の無音→次の発話、短い無音、閾値付近の変動、delta 間の判定窓分割を確認する。
- 先行保持の順序、リングの周回／満杯、PCM 領域の寿命、切断／モード停止を確認する。
- m5stack-cores3-realtime / m5stack-core2-realtime をビルドし、必要に応じて AtomS3R と TTS 構成を確認する。既存依存のみを使い、追加取得が必要な場合は事前確認する。
- 実機で無音時のマイク維持、応答再生、再生後の録音再開と RMS ログを確認する。実機確認はユーザー環境で行う。

## 実装・確認結果

- 判定窓 960 byte と先行保持 4800 byte を一括で PSRAM に確保する（追加 5760 byte）。
- delta をまたぐ窓は持ち越し、150 ms 受信が途絶えたら残りの短い窓も判定して発話末尾を保持する。
- 受信前の全 PCM サイズによるリング空き判定を、無音判定後の再生対象 PCM の空き判定へ移した。発話開始時は先行保持と開始窓をまとめて空き確認する。容量超過で当該受信中に追加済みの PCM がある場合も、既存の異常処理が再生要求前に破棄する。
- 通常の再生終了時は新しい判定窓と先行保持を維持し、発話状態を待機へ戻す。切断・異常・モード停止では全判定状態をクリアする。
- 静的確認: 全ゼロの連続入力は先行保持だけを更新し、再生リングや再生終了猶予を更新しない。発話中の無音は20窓（400 ms）で待機へ戻り、短い無音の後の継続閾値以上の窓では無音累計をゼロへ戻す。先行保持の周回時にも時系列順で再生リングへ追加する。
- 最大振幅 -32768 の480 sampleの平方和は 515396075520 で、64 bit に収まる。PCM16 の偶数境界、リング内の再生領域の保持、確保失敗と状態リセットも静的確認した。
