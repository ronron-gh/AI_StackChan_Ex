# GPTLive 応答音声の PSRAM リングバッファ再生

## 目的
CoreS3 + M5Unified で GPTLive の応答音声を再生する。マイクとスピーカーを半二重で切り替え、再生中も WebSocket 受信処理を継続する。

## 対象範囲・主な変更ファイル
- src/llm/ChatGPT/GPTLive.cpp / GPTLive.h: PCM 蓄積、再生状態管理、切断時の復旧。
- src/llm/RealtimeLLMBase.cpp / RealtimeLLMBase.h: GPTLive 専用処理をループから呼ぶ最小限の拡張。必要なら既存ダブルバッファの確保方法を調整する。
- doc/fw_design.md: 半二重音声処理、メモリ、異常時の扱いを追記。
- モード停止の後始末に必要な場合のみ、関連する停止処理を変更する。
既存の RealtimeChatGPT / GeminiLive / REALTIME_API_WITH_TTS の動作は維持する。API 接続方式・モデル選択の変更は対象外。

## 調査結果
- GPTLive は session.output_audio.delta を基底クラスの streamAudioDelta に渡している。
- streamAudioDelta はコールバック内で再生待ちするため、その間 WebSocket 受信が止まる。
- GPTLive では旧 API の録音停止・音声切替・録音再開イベント処理が無効化されている。
- TTS の outputTextQueue は std::deque<String>。受信と消費の分離を参考にし、音声用には容量制限付き PCM リングバッファを設ける。

## 実装方針
1. PCM16 / モノラル / 24 kHz のバッファを MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT で確保する。初期案は 512 KiB（約 10.9 秒）。デコード作業領域と再生用領域も容量を明示し、確保失敗を処理する。
2. 受信コールバックは Base64 のサイズ・デコード結果を確認して PCM を追加する。再生待ちや空き容量待ちで受信を止めない。
3. WebSocket ループ側で録音を停止し、既存の音声 mutex のもとで Mic.end → Speaker.begin を行う。再生中は入力音声を送信しない。
4. 再生領域は M5Unified が参照し終わるまで保持する。リングが空でも Speaker.isPlaying が真の間はマイクを再開しない。
5. リングとスピーカーの両方が空になったら Speaker.end → Mic.begin として録音を再開する。受信チャンク間の短い空白には短時間の猶予を設け、頻繁な切替を抑える。猶予の初期値は 150 ms とし、実機で調整する。
6. 容量超過・不正データ・初期化失敗・切断時の破棄／復旧を明示する。容量超過時は黙って PCM を部分追加せず、ログを残して再生状態を安全にリセットする。

## 設計上の注意点・副作用
- 再生中の音声割り込みは受け付けない半二重方式となる。
- ネットワークの遅延が猶予を超えるとマイク／スピーカーの再切替が発生し得る。
- mutex の取得・解放は同一タスクで対応させ、再生終了待ちで WebSocket を止めない。モード停止時に mutex やスピーカーを残さない。
- 手動の録音停止と自動の再開を区別し、停止操作を上書きしない。
- 既存ユーザー差分には触れず、変更をこの機能に限定する。

## 確認方法
- リングの周回、PCM サンプル境界、上限、確保失敗、再生領域の寿命、切断・モード停止を静的確認する。
- m5stack-cores3-realtime / m5stack-core2-realtime をビルド。共通部変更に応じて AtomS3R と TTS 構成も確認する。
- 依存取得にネットワークが必要なら、AGENTS.md に従って事前確認する。
- CoreS3 実機で短い応答、長い応答、連続チャンク、遅延、切断、録音停止／モード切替を確認する。実機確認はユーザー環境で行う。

## 実装時の具体化
- 再生用コピー領域は追加せず、リングの連続領域を最大 8192 byte ずつ直接再生する。再生中の領域は使用量に含め、完了まで上書きを禁止する。
- GPTLive は基底クラスの既存ダブルバッファを確保せず、PSRAM 使用量はリング 512 KiB + デコード領域 100 KiB とする。
- 録音要求と実録音状態を分離し、再生中の停止操作を尊重する。
- 異常時は後続音声の部分再生を避けるためセッションを切断し、再接続後はタッチで録音を再開する。モード停止も録音要求を解除する。
- 実行環境のシェル起動に問題があるため、Node 経由でローカル Python / PlatformIO を実行。キャッシュ済み依存のみを使い、依存のインストールとネットワーク接続を無効化する。
- モード停止時は WebSocket も切断し、復帰時の古い応答音声の再生を防ぐ。
